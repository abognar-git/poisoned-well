# Data dictionary

Everything in `data/panel/` and `data/archive/` is regenerated by scripts in this
repository from the sources named below. Nothing here is hand-edited.

Read the **Censoring and limits** section before computing anything. Two of the three
limits below have already produced a wrong number in this project once.

---

## `panel/` — the network's credit graph

Derived by `scripts/derive_feeder_index.py` from CheckFirst's per-mirror files
(`data/raw/pravda/json/*_viz.json`, fetched by `scripts/fetch_pravda.py --all`, gitignored
because it is upstream's to distribute).

**A credit is the mirror's own claim about where it took an item.** It is not evidence
that the credited channel participated in, cooperated with, or is aware of the network.
Every row carries `relationship = credited-by-mirror` to keep that on the record.

### `mirror_day.csv` — 70,741 rows

| column | type | meaning |
|---|---|---|
| `mirror` | string | mirror short name (`hungary`, `romania`, …) |
| `date` | ISO date | day |
| `articles` | int | articles CheckFirst observed that day |

### `mirror_source_day/YYYY-MM.csv` — 349,004 rows across 39 monthly files

| column | type | meaning |
|---|---|---|
| `mirror` | string | crediting mirror |
| `date` | ISO date | day |
| `source` | string | credited source, verbatim (`Telegram: handle`, a domain, `MAX …`) |
| `source_type` | enum | `telegram` · `domain` · `max` · `other` |
| `credits` | int | items the mirror credited to that source that day |
| `relationship` | const | `credited-by-mirror` |

Month-partitioned so a scheduled regeneration rewrites one file, not forty megabytes.

### `source_index.csv` — 9,905 rows, one per source

| column | type | meaning |
|---|---|---|
| `source` | string | verbatim name |
| `handle` | string | the part after `: `, or the whole name |
| `source_type` | enum | as above |
| `total_credits` | int | summed **across every mirror** — not one mirror's count |
| `mirrors_fed` | int | distinct mirrors crediting it |
| `exclusivity` | enum | `exclusive` (1 mirror) · `shared` (2–4) · `network-wide` (5+) |
| `exclusive_to` | string | the mirror, when `exclusive` |
| `first_seen_daily` / `last_seen_daily` | ISO date | first/last appearance **in the censored daily panel**, blank if it never entered a top-10 |
| `mirrors_with_daily_series` | int | mirrors where a daily series exists for it |
| `mirrors_preview` | string | up to 12 mirror names, `…` if truncated — **display only** |
| `relationship` | const | `credited-by-mirror` |

⚠ **Do not compute on `mirrors_preview`.** It stops at 12 names. Join
`source_mirror_edges.csv` instead.

### `source_mirror_edges.csv` — 68,912 rows

The complete bipartite graph: `source`, `mirror`, `credits`, `relationship`. This is the
file to join against.

### `mirror_meta.csv` — 101 rows

`mirror`, `domain`, `total_articles`, `first_day`, `last_day`, `sources_listed`,
`avg_alternates`, `languages`.

## `archive/` — captured specimens

Append-only, built by `scripts/capture_specimens.py` and merged by
`scripts/archive_specimens.py`. Month-sharded JSONL, one object per line.

| field | meaning |
|---|---|
| `site` | capture source id (`pravda-hu`, `tg-rybar`, `rt-ru`, …) |
| `tier` | `origin` (Telegram) · `launderer` (Pravda mirror) · `outlet` (sanctioned outlets) |
| `date` | publication date where the listing gives one. Reaches back further than the collection window — front pages link to their own archives, so Zvezda alone contributes items from 2022. Use `first_seen` for when we saw it. |
| `date_is_capture` | present and true when the listing gave **no** date and `date` is our capture day |
| `published_at` | full ISO timestamp, Telegram only — minute resolution |
| `first_seen` | when this project first observed the item. **Not a publication time.** |
| `title` | the captured text (see `unit`) |
| `unit` | `headline` (mirror, outlets) · `post_excerpt` (Telegram) |
| `chars` | length of the full text when `title` is truncated. Telegram posts run to a median of ~700 characters and a maximum near 1,900, so **no post fits in the 120-character excerpt** — `title` is the opening of a post, not a title, and `chars` is how a consumer knows what fraction they hold. Absent when nothing was cut — and also absent on rows captured before 2026-08-14, where the full text was discarded at capture time and cannot be recovered. A `post_excerpt` ending in `…` with no `chars` is truncated by an unrecorded amount. |
| `lang` | `hu` · `cyr` · `lat` · `other`, from a crude script-and-function-word heuristic. `other` is any script neither lexicon covers, and is the only value that yields `unscored`. |
| `theme` | one of five topics · `filler` (scored, matched nothing) · `unscored` (no lexicon for this language) |
| `category` | the publisher's own section label, or the channel handle |
| `source` | for mirror articles, the origin the mirror credits |
| `url` | where present |

## Censoring and limits

**1. `sourcesByDay` is top-10 per mirror per day.** The daily panel is right-censored, and
the cut varies by mirror and by month. Any *share of credits* computed from
`mirror_source_day` has a denominator that silently changes underneath it. Condition on the
top-10 set explicitly, or use `source_index.csv` / `source_mirror_edges.csv`, which come
from the uncensored per-mirror totals and have no dates.

**2. Daily counts are collection-side.** A fall in `articles` is jointly a publishing
decision and a change in what the collector saw. These files cannot separate them, and this
project's own headline finding is bounded by exactly that.

**3. `total_credits` in `source_index.csv` sums across mirrors.** A source credited 37,940
times by the Hungarian mirror and 115,832 times elsewhere shows 153,772. For one mirror's
count, filter `source_mirror_edges.csv`.

**4. The archive is a sample, not a census.** The capture reads front pages on a schedule
with a per-source cap and a round-robin fill, so it is biased toward whatever is on a
listing when the job runs — diurnally, at minimum. It is not a complete record of what any
source published. `theme` is a disclosed keyword heuristic; `lang` is a crude script test.
Both were wrong in a specific, documented way until 2026-08-13 (see `RESEARCH.md`,
correction 5).

**5. Personal-smear items are withheld** by a fixture-tested filter, so the archive is
deliberately not exhaustive. Those items are described in the case files rather than
reproduced.

## An observation, stated with its control

4,574 of 9,905 sources are credited by exactly one mirror. The Hungarian mirror has **none**:
all 939 sources it credits also feed at least one other mirror, 43.1 on average, minimum 2.

That looks like a Hungary-specific fact and it is not. Romania is also zero, of 924. The
range across comparable mirrors is wide — Estonia 818 of 1,000 (81.8%), Slovakia 19.8%,
Bulgaria 18.7%, Czechia 12.8%, Hungary and Romania 0%. So there are at least two regimes in
this network, and the Hungarian mirror sits in the pure-rebroadcast one **with company**.
Any claim that Hungary is uniquely without a local recruitment layer is wrong on this data.
